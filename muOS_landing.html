BETA-X 결론
오버헤드의 원인은
"복사 비용"이 아니라
전환 비용이었다

yield를 생략한 atomic 직접 통신 실험에서 32배 속도 향상을 확인.
ALPHA 2에서 이미 Zero-copy IPC를 구현해둔 상태였기 때문에,
복사 최적화는 큰 데이터에서 오히려 역효과(0.4×)까지 발생.

❌ 초기 가설

"메시지 복사를 줄이면 (공유 메모리) 빨라질 것"

✅ 실제 결과

"컨텍스트 스위치를 생략하면 32배 빨라진다"

Policy Engine

OS가 스스로 최적화한다

사용자가 "배터리 절약"이라고 선언하면,
OS가 알아서 모든 파라미터를 도출한다.

🧠
행동 분류
voluntary_yields / forced_preempts를 PCB에 누적.

EMA(지수이동평균)로 I/O바운드 vs CPU바운드 실시간 분류.
⌨️
포그라운드 부스트
키보드 입력 감지 즉시 포그라운드 프로세스에 High 우선순위 + 슬라이스 부스트.

타이핑하는 동안 백그라운드 빌드가 체감상 느려지지 않음.
⚖️
Starvation 방지
Aging 알고리즘 — 오래 기다린 프로세스의 우선순위를 강제로 올려
낮은 우선순위 작업도 결국 실행되도록 보장.
🔌
Hardware Fingerprinting
부팅 시 ACPI + PCI 스캔 → P-Core/E-Core 구성 파악.
울트라북이면 절전, 데스크탑이면 성능 프로파일 자동 적용. (목표)
⚡
Fast Channel (다음 단계)
BETA-X에서 발견한 32배 효과를 구현.
"생성은 엄격하게, 사용은 가볍게" — Capability 검증 우회 없이 전환 비용만 제거.
📊
ML 로드맵
